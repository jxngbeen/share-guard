# share-guard

글 작성 중 민감정보 후보를 찾아 Chrome 확장 팝업으로 알려주는 보조 도구입니다. 제품 실행에는 AI API나 외부 서버를 사용하지 않습니다.

## v0.4.5

실제 확장과 웹 체험을 같은 Graphite 디자인으로 맞추고 승인된 01 REDACT 심볼·워드마크를 적용했습니다. 상단 여백을 줄여 작업 버튼과 하단 안내가 보이며, 많은 후보는 목록 안에서 스크롤합니다. 확장의 감지·편집 엔진은 v0.4.3과 같습니다.

[소개·체험 사이트](https://share-guard.duskyscarf34.chatgpt.site/) · [v0.4.5 Release](https://github.com/jxngbeen/share-guard/releases/tag/v0.4.5) · [확장 ZIP 다운로드](https://github.com/jxngbeen/share-guard/releases/download/v0.4.5/share-guard-v0.4.5.zip)

이 저장소는 검토된 제품 소스·사용 안내·합성 테스트를 제공하는 최종 배포 저장소입니다. 설치 파일과 SHA256은 [배포 안내](DEPLOYMENT.md)에서 확인할 수 있습니다.

- 전화번호·이메일·주민번호 형태·계좌번호·카드번호·여권번호·API 키와 토큰 후보를 검사합니다.
- 전화는 국번 3~4자리의 넓은 후보를 찾으므로 `010-000-0000`도 포함합니다. 정상 가입번호인지 확인하거나 실제 소유자를 조회하지 않습니다.
- `000000 0000000`과 `000000-0000000` 모두 주민번호 **형태**로 감지합니다. 발급 가능 여부나 실재성을 판단하지 않습니다.
- 팝업에 **행·글자 위치와 주변 문장**을 표시합니다. 발견한 값들은 문맥에서도 유형명으로 가립니다.
- 입력을 **1초 멈춘 뒤** 경고하며, 같은 편집 영역에서 알린 동일 정보 조합은 반복해서 열지 않습니다. 최근 50개 조합을 기억하며 페이지 새로고침 시 초기화합니다.
- 같은 본문에서는 후보 선택을 다시 확인·팝업 재개방 후에도 유지합니다. 본문·입력 대상 변경, 일시정지, 페이지 새로고침 시 초기화합니다.
- 후보 목록의 **전체 선택·전체 해제**로 체크 상태를 한 번에 바꿉니다. 선택 개수를 표시하며 0개일 때 수정 버튼은 비활성화됩니다.
- 후보를 선택해 **선택 항목 가리기·삭제·직전 수정 복원**을 실행합니다. 밝은 가리기 버튼과 짙은 회색 삭제 버튼을 사용하며, 미리보기·복사 단계가 없습니다.

[감지 규칙과 예시](DETECTION_RULES.md) · [검증 결과](TESTING.md) · [기존 회귀 평가](DETECTION_EVALUATION.md) · [새 합성 140건 평가](DETECTION_HOLDOUT.md) · [남은 개선 사항](KNOWN_ISSUES.md) · [변경 이력](CHANGELOG.md) · [배포·릴리스](DEPLOYMENT.md)

2026-10-27 새 합성 140건 평가는 사전 기대와 139건 일치, TP 70 / FP 1 / FN 0입니다. 1건은 엄격한 010 자릿수 기대와 넓은 후보 감지 정책의 차이로, 후속 검토에서 현재 후보 범위를 유지했습니다. 원본 결과를 140/140으로 바꾸지 않았으며 실사용 정확도나 독립된 사람의 평가로 일반화하지 않습니다. 구체적인 검증 범위는 위 문서를 참고하세요.

## 설치·업데이트

1. Chrome 127 이상에서 `chrome://extensions`를 열고 개발자 모드를 켭니다.
2. 소스에서 설치할 때는 **압축해제된 확장 프로그램 로드**에서 `extension` 폴더를 선택합니다. Release ZIP을 받았다면 압축을 풀고 `manifest.json`이 바로 들어 있는 폴더를 선택합니다. ZIP 파일 자체를 선택하지 않습니다.
3. 기존 설치는 해당 확장의 **새로고침**을 누르고 버전 **0.4.5**를 확인합니다. 다시 삭제·설치할 필요는 없습니다.
4. 작성 중인 글을 보존한 뒤 글쓰기 페이지도 새로고침합니다.
5. 검사할 사이트의 접근 권한을 허용합니다. 접근이 클릭 시에만 허용되면 상시 검사가 작동하지 않습니다. 아이콘을 고정하면 후보 개수 배지를 볼 수 있습니다.

HTTP/HTTPS 문서와 접근 가능한 프레임에서 동작합니다. Chrome 내부 페이지나 웹 스토어 등 실행 제한 페이지에서는 사용할 수 없습니다. 자동 팝업은 활성 탭·활성 브라우저 창에서만 열며, 열기가 거절되면 아이콘의 배지로 확인합니다.

## 사용 범위

| 입력 영역 | 감지 | 가리기·삭제·직전 복원 |
| --- | --- | --- |
| textarea | 지원 | 지원 |
| 한 줄 text/search/tel/email/url 입력 | 지원 | 지원, email은 커서 위치 지정 불가 |
| 일반 contenteditable | 지원 | 미지원 |
| 네이버 PC 블로그 PostWriteForm 본문 | 별도 연동 | 별도 연동 |
| 비밀번호·숨김·비활성·읽기 전용 입력 | 제외 | 제외 |
| 이미지·첨부 파일·이름·주소 의미 분석 | 미지원 | 미지원 |

현재 입력하는 영역을 중심으로 검사합니다. 행 번호는 화면의 자동 줄바꿈이 아닌 본문 개행 기준이며, 네이버는 문단 기준입니다. 위치 표시는 안내이며 본문을 자동 스크롤하거나 강조하는 기능은 없습니다.

네이버에서는 문단 ID와 텍스트를 문서 모델과 대조하고 변경한 문단의 텍스트 노드만 복원합니다. 문서 전체를 재설정하지 않고 문단 변경을 네이버 이력에 기록하므로 기존 실행 취소·다시 실행을 유지합니다. 한 번의 여러 항목 수정은 네이버 실행 취소 한 단계이며, 확장의 복원도 별도 한 단계로 기록됩니다. 페이지 새로고침·일시정지·입력 대상 변경 시 복원 정보는 사라집니다. 수정 대상 문단의 텍스트·서식이 바뀌면 덮어쓰지 않도록 복원을 거절합니다. 다른 문단에 추가한 글은 유지하면서 복원할 수 있습니다. 이미지·수식 등 비텍스트 노드를 포함한 수정 대상 문단은 호환성 확인에 실패하면 원문을 변경하지 않습니다.

글이 바뀌었다는 안내가 나오면 **다시 확인**합니다. **이 탭 검사 끄기**는 현재 탭의 모든 프레임에 적용되며 새 프레임·페이지 새로고침 뒤에도 유지됩니다. 다른 탭에는 영향을 주지 않습니다. 다시 켜거나 탭을 닫으면 해제되고, 브라우저 재시작 시에도 초기화됩니다. 한글 조합 이벤트가 진행 중이면 완료 후 검사합니다.

## 로컬 실행

소개·체험 사이트는 다음 명령으로 실행합니다. 빌드에는 Node.js 24와 `zip` 명령이 필요합니다. 별도 npm 패키지나 API 키는 사용하지 않습니다.

```sh
npm run site:build
npm run site:preview
```

`http://127.0.0.1:4175`에서 열립니다. 포트가 사용 중이면 `PORT=4187 npm run site:preview`처럼 바꿉니다. 결과물은 `dist/site/`, 설치 ZIP은 그 안의 `downloads/`에 생성됩니다. [사이트 구성과 검증 범위](website/README.md), [로고 원본](brand/README.md)을 참고하세요.

Node.js 24에서 별도 패키지 설치 없이 실행할 수 있습니다.

```sh
npm test
npm run demo
```

`http://127.0.0.1:4173`에서 **합성 예시 불러오기**를 누르면 7종 후보를 확인할 수 있습니다. 포트가 사용 중이면 `PORT=4174 npm run demo`처럼 변경합니다. `/rich.html`은 서식·프레임, `/qa.html`은 입력 유형별 회귀 테스트 자료입니다. `/naver-fixture.html`은 합성 모델이며 실제 네이버 페이지나 계정 자료를 포함하지 않습니다.

## 개인정보·권한·한계

원문을 외부로 전송하거나 영구 저장하지 않습니다. 원문·탐지 결과·경고 중복 식별 정보·직전 복원 데이터는 페이지와 팝업의 메모리에서 처리합니다. `storage.session`에는 탭·문서·프레임 식별자, 마지막 입력 활동 시각, 후보 수, 탭별 일시정지 상태만 저장합니다. 후보 선택은 숫자 인덱스와 본문 버전으로 현재 문서 메모리에만 보관합니다. 네이버 수정용 문서 데이터는 확장 내부 메시지로 일시 전달되며 storage에 넣지 않습니다.

자동 실행에 HTTP/HTTPS 사이트 접근, 상태 관리에 `storage`, 네이버 문서 API 연동에 `scripting`과 `https://blog.naver.com/*` 호스트 권한을 사용합니다. Chrome 사이트 접근 설정으로 범위를 제한할 수 있습니다.

이 도구는 **후보를 알려주는 보조 도구**입니다. 20,000자 초과 글은 검사하지 않으며, 모든 개인정보를 탐지하거나 실제 자격증명의 유효성을 검증하지 않습니다. 게시·전송·원래 사이트의 자동 저장을 차단하지 않습니다. 네이버 내부 구현 변경과 사이트별 입력 처리에 따라 호환성 차이가 생길 수 있습니다.

개발 과정에서 AI 코딩 도구를 활용했으며 제품 실행에는 AI를 사용하지 않습니다. 이 저장소에는 제품 소스·사용 안내·재현 가능한 합성 테스트만 포함합니다.
